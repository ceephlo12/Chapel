# Project: French Quarter Wedding Chapel Concept Redesign

This is an unofficial concept redesign mockup for presentation purposes only.

## Goal

Build a polished, functioning mockup for a luxury French Quarter wedding chapel website.

The mockup should show:
- wedding package browsing
- mock availability calendar
- save-the-date / soft hold request flow
- New Orleans weekend events feature
- white-glove chapel team help path
- Teresa Newman Photography feature
- chapel founder legacy section

## Design Direction

High-end Southern wedding magazine.

The site should feel:
- elegant
- romantic
- editorial
- warm
- intimate
- historic
- deeply New Orleans

Use:
- ivory
- warm cream
- champagne gold
- antique brass
- deep espresso
- elegant serif headings
- clean readable body text
- editorial image layouts
- generous spacing
- refined buttons
- soft texture
- subtle French Quarter details

Avoid:
- SaaS look
- tech startup design
- cheap wedding template look
- pink glitter bridal styling
- generic booking app feel

## Content Rules

### Chapel Founder Legacy

Keep Rev. Tony as part of the chapel's founding story and legacy.

Do:
- mention him respectfully as a founder / part founder
- mention that he has passed away, if appropriate
- allow a tasteful legacy photo section
- keep the tone warm, brief, and respectful

Do not:
- erase him completely
- present him as a current ceremony leader
- present him as currently running the chapel
- present him as currently available

### Availability Language

Remove all around-the-clock wedding or availability language.

Do not say:
- always open
- weddings at unrestricted hours
- available day or night
- book any time

Use:
- "Ceremony times are available by request and confirmed by the chapel team."
- "Select a preferred date and time, and the chapel team will follow up to confirm availability."
- "Availability varies by date, package, and chapel schedule."

### Creative Partner

Teresa Newman Photography is the only named photography reference allowed.

Do not mention other photography vendors.

### Booking Language

This mockup does not confirm real bookings.

Do not say:
- finalized reservation
- promised date
- immediate reservation
- payment complete

Use:
- date request
- soft hold request
- availability request
- chapel team confirmation

### Mockup Disclaimer

The footer must include:
"Unofficial concept redesign for presentation purposes only."

## Technical Rules

Use:
- Next.js
- TypeScript
- Tailwind
- local mock data

Do not add unless explicitly requested:
- database
- payments
- authentication
- admin dashboard
- real calendar integration
- scraping
- unnecessary libraries

## Data Files

Use local data files:
- `/lib/data/packages.ts`
- `/lib/data/availability.ts`
- `/lib/data/cityEvents.ts`
- `/lib/data/siteContent.ts`

## Workflow

Work in small steps.
After each step, summarize:
- what changed
- files changed
- what still needs work

Use simple, readable code.
Prefer easy-to-replace mock data over complex abstractions.
